# WoT Blitz VPN

Android VPN-клиент для **World of Tanks Blitz от Wargaming**.
Единственный разрешённый пакет: `com.wargaming.wot.blitz`.
Пакеты Lesta и других приложений не добавляются в VPN.

## Текущий этап: модуль 2, версия 0.2.0

Готовы Gradle-проект, манифест, каркас `WotVpnService`, политика per-app VPN,
экран на Jetpack Compose, ввод ссылки конфигурации, запросы разрешений,
уведомления, unit-тесты и GitHub Actions. У приложения есть launcher activity.

**Это ещё не рабочий VPN-клиент.** Прокси-ядра и `tun2socks` пока нет.
После корректного ввода и согласия на VPN сервис сообщает об отсутствии ядра
и завершает работу. Он намеренно **не вызывает `Builder.establish()`**:
TUN без обработчика пакетов заблокировал бы трафик игры. Состояние
«Подключено» не выставляется ни таймером, ни кнопкой, ни результатом согласия.

### Экран и разрешения

- Большая кнопка «Подключить / Отключить», наблюдаемый статус сервиса,
  поле конфигурации с переключателем видимости и очисткой, подсказка о текущем
  этапе и поддерживаемых протоколах. Экран прокручивается и учитывает системные
  отступы и клавиатуру.
- Игра проверяется при открытии/возвращении в приложение, перед запросом
  разрешений и ещё раз перед запуском сервиса. Если её нет, сразу видно
  **«World of Tanks Blitz не установлен»**, а подключение недоступно.
- Ввод принимает **одну ссылку** `vless://`, `vmess://`, `trojan://` или `ss://`,
  максимум 32 768 символов. Проверяются схема, наличие содержимого и отсутствие
  внутренних переносов/управляющих символов. Это не полный разбор протокола:
  UUID, пароль, транспорт, TLS, параметры сервера и UDP проверит модуль ядра.
  JSON, subscription URL и списки ссылок в этом этапе не поддерживаются.
- Android 13+: уведомления запрашиваются по нажатию «Подключить». Отказ
  не блокирует VPN; доступен переход в системные настройки уведомлений.
- Согласие VPN запрашивается через `VpnService.prepare()` и Activity Result API.
  Отмена не запускает сервис. После callback запуск выполняется только при
  `Lifecycle.State.RESUMED`, а не из фонового callback разрешения.
- Ожидающий запрос сохраняется в `ViewModel` при повороте экрана; повторные
  нажатия не создают дубликаты диалогов. Кнопка отмены очищает ожидающий запрос.
  Поздние результаты без ожидающего запроса игнорируются, в том числе после
  пересоздания процесса: автоматического подключения со старым согласием нет.
- Уведомление сервиса открывает главный экран, не передавая в него секреты.

### Конфиденциальность конфигурации

Ссылка может содержать UUID и пароли. Поле по умолчанию замаскировано,
`FLAG_SECURE` запрещает снимки экрана и показ содержимого в списке недавних
приложений. Для ввода отключена автокоррекция, используется password keyboard.
Приложение не читает буфер обмена автоматически — вставка штатными средствами
поля по действию пользователя.

Черновик и ожидающая ссылка находятся только в памяти `ViewModel`, не в
`SavedStateHandle`, `rememberSaveable`, SharedPreferences или файлах.
При повороте поле сохраняется, после завершения процесса — нет. При очистке
`ViewModel` ссылки на черновик сбрасываются. Гарантия физического обнуления
неизменяемых строк JVM не заявляется. Конфигурация не выводится в логи и не
входит в текст уведомлений. В сервис она передаётся явным Intent внутри
приложения; `START_NOT_STICKY` не запрашивает автоматическую повторную доставку.

### Split tunneling и безопасность

- Политика начинается с единственного
  `Builder.addAllowedApplication("com.wargaming.wot.blitz")`.
- Ошибка разрешения пакета не превращается в VPN для всего телефона;
  создание TUN не продолжается. Проверка игры повторяется в сервисе.
- `<queries>` позволяет обнаружить игру при package visibility на Android 11+.
- IPv4 и IPv6 имеют отдельные адреса и default routes внутри политики VPN.
  Эти маршруты относятся только к allowlist игры, а не ко всему устройству.
  `allowBypass()`, `allowFamily()` и исключения для других приложений не включены.
- Сервис защищён `android:permission="android.permission.BIND_VPN_SERVICE"`.
  Это требование к вызывающей стороне сервиса, а не выдаваемое приложению
  runtime-разрешение; добавлять его как `<uses-permission>` не требуется.
- Для Android 14+ объявлен foreground service типа `specialUse` с описанием.
  Always-on VPN отключён в метаданных, чтобы каркас не использовался как
  неработающий постоянный VPN.

### UDP и порты игры

Политика не ограничивает транспорт и порты: в будущем TUN должен передавать
весь IP-трафик игры, включая UDP `12000–43000` и TCP `443`, `5222`, `8886`.
Сам `VpnService.Builder` **не реализует передачу UDP**. В модуле 3 нужны
двусторонний UDP relay в `tun2socks`, UDP-совместимое ядро и поддержка UDP
выбранным сервером. До их интеграции передача TCP, UDP и DNS не заявляется.

## Сборка только через GitHub Actions

Локальная сборка в песочнице не выполняется. Workflow
`.github/workflows/build.yml` запускается на push в `main` или `arena/**`,
на pull request и вручную через **Actions → Android APK → Run workflow**
для нужной ветки.

Окружение: JDK 17, Gradle 8.11.1, AGP 8.9.2, Kotlin / Compose compiler 2.1.21,
Compose BOM 2025.04.01, Android SDK / target 35, Build Tools 35.0.0.
Минимальная версия — Android 8.0 (API 26). Wrapper и версия дистрибутива
зафиксированы; скачивание Gradle проверяется по SHA-256. GitHub Actions
закреплены по commit SHA.

CI выполняет:

1. Проверку Wrapper и публичного debug-ключа.
2. `./gradlew --no-daemon testDebugUnitTest lintRelease`.
3. `./gradlew --no-daemon assembleRelease`.
4. `apksigner verify` для готового APK.
5. Загрузку `app-release.apk` в artifact `WoT-Blitz-VPN-<run_number>`;
   отчёты тестов и lint сохраняются отдельно. Срок хранения — 14 дней.

Unit-тесты покрывают единственный allowed package, отсутствие глобального
fallback, IPv4/IPv6, формат ввода, отмену согласия, необязательные уведомления,
дубликаты нажатий, поздние callbacks, удаление игры во время согласия, ошибки
старта и передачу реальной ошибки сервиса без фиктивного состояния «Подключено».
JVM-тесты не заменяют проверку системных диалогов и UDP на Android-устройстве.

Release APK подписывается **публичным debug-ключом** из `signing/` с alias
`androiddebugkey` и паролями `android`. Это только личная тестовая подпись,
не для Google Play. Ключ постоянный, поэтому следующие APK из CI подписываются
тем же сертификатом. Подробности: [signing/README.md](signing/README.md).
Workflow не требует GitHub-токена в исходниках или chat-секретов.
